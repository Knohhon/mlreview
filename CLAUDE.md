# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Проект

MLReview — open-source ассистент-критик для ML-экспериментов. Требования (с идентификаторами FR-*/NFR-*), критерии приёмки и этапы разработки описаны в `docs/MLReview-analysis.md` — это основной источник контекста о проекте. Пользовательские сценарии — в `docs/User-cases-MLReview.md`.

Статус: этап 0–1, есть только скелет пакета. Подкоманды CLI (`review`, `metrics`, `diagnose`, `ask`) пока заглушки, возвращают код 1 с сообщением «не реализована» — `tests/test_cli.py` это проверяет, при реализации команды тест нужно обновить. Первые целевые задачи — классификация и регрессия на табличных данных (линейные модели), первый трекер — MLflow.

## Команды

```bash
pip install -r requirements.txt         # окружение L0: пакет с extras mlflow и dev + scikit-learn для бенчмарка
pip install -e ".[dev]"                 # минимальная установка: пакет и dev-инструменты (Python 3.10+)
ruff check .                            # линтер
ruff format .                           # форматирование
pytest                                  # все тесты
pytest tests/test_cli.py::test_version  # один тест
python -m mlreview --help               # запуск CLI (или `mlreview`)
```

Перед коммитом `ruff check .`, `ruff format --check .` и `pytest` должны проходить (скилл `check`). CI (`.github/workflows/ci.yml`) запускает то же самое, тесты — на Python 3.10–3.13, поэтому синтаксис должен быть совместим с 3.10. Настройки ruff — в `pyproject.toml` (`[tool.ruff]`), длина строки 100. Версия пакета задаётся в `src/mlreview/__init__.py` (hatch читает её оттуда).

## Порядок разработки (обязательный)

Любая разработка — фича, анализатор, команда, исправление бага — идёт по скиллу `develop`:

1. **Спецификация.** Ожидаемое поведение фиксируется в `docs/specs/<имя>.md` (шаблон — `docs/specs/README.md`): пункты B*/E* «дано · когда · тогда» со ссылками на FR/NFR/S/B.
2. **Тесты.** Под каждый пункт — тест, докстринг которого начинается с номера пункта (`B1: …`); убедиться, что новые тесты красные по правильной причине.
3. **Код.** Минимальная реализация до зелёных тестов; тесты под код не подгоняются.
4. **Проверки.** `ruff check`, `ruff format --check`, `pytest` (скилл `check`).
5. **Документация.** Актуализировать CLAUDE.md и скиллы; по остальным markdown — предупредить о несоответствиях и предложить правки (скилл `docs-sync`, `python .claude/hooks/doc_sync.py report`).

Хуки в `.claude/settings.json` (скрипты в `.claude/hooks/`, их тоже проверяет ruff):
- после каждой правки `.py` — `ruff check` и `ruff format --check` этого файла; ошибки возвращаются Claude;
- в конце хода, если менялся код, — полный `ruff check`, `ruff format --check` и `pytest`; при падении Claude должен исправить или объяснить (например, «тесты написаны, реализации ещё нет»);
- в конце хода, если с прошлой актуализации изменились файлы, — `doc_sync.py` возвращает Claude список изменений и автоматические находки (битые ссылки на пути, неизвестные FR/NFR); дальше по скиллу `docs-sync`: CLAUDE.md, скиллы и настройки Claude актуализирует сам, по README и `docs/` — предупреждает о несоответствиях и предлагает правки, не применяя их без согласия (спецификация — `docs/specs/doc-sync.md`, снимок — `.claude/state/`, в git не попадает);
- в конце хода и сессии — сохранение диалога в `docs/dialogs/claude-<дата>-<сессия>.md`;
- перед командами Bash — блокировка чтения `docs/dialogs/`.

Тестовые стражи (`docs/specs/invariant-guards.md`): `tests/test_architecture.py` падает, если код вне `src/mlreview/adapters/` импортирует фреймворк обучения или трекер; `tests/conftest.py` блокирует сеть во всех тестах.

## Архитектура

- `src/mlreview/` — пакет (src-layout): `core` (спецификация задачи, контракт прогона, хранилище находок, журнал решений), `adapters` (MLflow, файлы), `analyzers`, `metrics`, `llm`, `playbooks`, `mcp_server`, `cli.py`. Докстринг каждого подпакета ссылается на требования FR-*, которые он закрывает; в новом коде следовать этой привычке.
- Поток данных: адаптер → контракт прогона → детерминированные анализаторы → *находки* (важность, доказательства) → хранилище находок → CLI / MCP / проактивное ревью. LLM-слой только синтезирует гипотезы поверх находок.
- Ключевые инварианты (проверяются тестами по мере реализации):
  - **NFR-01:** ядро не импортирует фреймворки обучения и трекеры (страж — `tests/test_architecture.py`); в `[project] dependencies` только вычислительные библиотеки (numpy, scipy, pandas, pyyaml, pydantic); интеграции — через extras в `pyproject.toml` (например, `mlflow`) и только в `src/mlreview/adapters/`; scikit-learn — только для бенчмарка (`requirements.txt`).
  - **FR-L02:** каждое число в ответе LLM берётся из фактов анализаторов, каждое утверждение ссылается на находку.
  - **NFR-03:** всё детерминированное работает без LLM; тесты проходят офлайн (сеть заблокирована в `tests/conftest.py`).
  - **NFR-04:** данные не покидают машину; во внешнюю LLM — только агрегаты и явно выбранные примеры.
  - **NFR-05:** факты воспроизводимы — сиды (например, бутстрапа) фиксированы.

## Предметная модель и правила поведения

Источник — `docs/MLReview-analysis.md` (требования) и `docs/User-cases-MLReview.md` (сценарии S01–S30, сквозные X1–X6).

- **Термины:** *спецификация задачи* (YAML: тип задачи, выход, цена ошибок, сегменты, `split_strategy`, версия данных, известные проблемы); *контракт прогона* (предсказания, метки, id и метаданные примеров, конфиг, кривые, версия данных); *анализатор* (детерминированная проверка → факты); *находка* (severity, доказательства — например id примеров, статус: новая/принята/отклонена/исправлена); *плейбук* (пакет знаний по типу задачи).
- **Объём L0 (текущая цель):** FR-C01 (спецификация задачи + валидация), FR-C02 (контракт прогона), FR-C03 (адаптер MLflow), FR-D01 (сравнение прогонов с CI и значимостью), FR-D02 (срезы), FR-D03 (проверки данных), FR-R01 (CLI). Должны ловиться дефекты бенчмарка B01 (дубли train/test), B02 (временная утечка), B12 (регрессия сегмента). Остальное — L1+; не реализовывать раньше без запроса.
- **Явная деградация (X1–X6):** не падать и не молчать — сообщать, что не сделано и почему. Неполный контракт → перечислить пропущенные анализаторы и недостающие поля, остальные работают. Без LLM команды вроде `ask` отвечают «требует LLM», а не падают. LLM-ответ с числом вне фактов блокируется. Отклонение critical-находки требует причины.
- **Инструмент не применяет изменения сам** — только предлагает изменение и (различающий) эксперимент.
- Подкоманды и флаги в сценариях (`metrics init`, `diagnose data`, `dismiss`, `--format json --fail-on critical` и т. п.) иллюстративные, а не утверждённый интерфейс. Предложения из раздела «Сводка и предложения в требования» (S18–S30, B13, повышение FR-C06 до Must и др.) ещё не приняты в требования.
- Открытые вопросы, от которых зависит дизайн: формат плейбука (только YAML или YAML + Python-проверки); как ловить B04/B10 (анализ кода пайплайна или описание в спецификации); сбор сигнала полезности (телеметрия или опросы).

## Соглашения

- Документация, докстринги и сообщения пользователю пишутся по-русски (поэтому в ruff отключены RUF001–RUF003).
- `README.md` — только о продукте: назначение, возможности, статус, планы, установка и разработка самого пакета. Настройки и процесс работы с Claude (CLAUDE.md, `.claude/`, скиллы, хуки, `docs/specs/` как часть процесса, диалоги) в README не добавлять и не предлагать — они описаны здесь.

## Ограничения

- **Не читать файлы диалогов.** Папка `docs/dialogs/` содержит сохранённые диалоги (переписку), а не документацию проекта. Не открывать, не искать по ним и не использовать их содержимое как контекст — ни через Read/Grep/Glob, ни через команды оболочки (`cat`, `grep`, `head` и т. п.). Исключение — только прямая просьба пользователя прочитать конкретный файл диалога; технически Read этой папки запрещён в `.claude/settings.json`, так что для этого пользователь должен сам снять запрет.
- Рекурсивный поиск в оболочке — только с `--exclude-dir=dialogs` или по конкретным путям (`src/`, `tests/`); `.ignore` исключает папку из ripgrep и поиска Claude Code.
- Диалоги с Claude записываются в `docs/dialogs/` автоматически хуком; вручную их не писать и не править (Edit/Write папки запрещены).
- Перемещать, переименовывать или удалять файлы в `docs/dialogs/` можно, не открывая их содержимого (`ls`, `mv`, `rm`, `git add/mv/rm` хук разрешает).
