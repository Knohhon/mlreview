# Адаптер MLflow

Опора: FR-C03 (адаптер MLflow, L0 · Must), FR-C02 (адаптер отдаёт контракт прогона; формат — `docs/specs/run-contract.md`), FR-R01 (CLI), S02 (прогоны логируются в MLflow), S27 (адаптер сообщает, каких полей не хватает и что из-за этого недоступно), X1 (неполный контракт), NFR-01 (mlflow только в `mlreview.adapters` и extra `mlflow`), NFR-03 (тесты офлайн).

Адаптер `mlreview.adapters.mlflow_adapter` читает прогон MLflow и собирает из него контракт через `build_run_contract` (FR-C02). MLflow не хранит предсказания в стандартном виде, поэтому таблицы контракта лежат в артефактах прогона по соглашению; остальное берётся из штатных сущностей MLflow. Модуль `mlflow` импортируется лениво: без extra `mlflow` пакет и остальные команды работают, а адаптер явно сообщает, что нужно установить.

```python
from mlreview.adapters.mlflow_adapter import load_mlflow_contract, log_contract_artifacts

# в скрипте обучения, внутри mlflow.start_run():
log_contract_artifacts(predictions, examples=examples, data_version="ds-v3")

# при анализе:
contract = load_mlflow_contract(spec, run_id, tracking_uri="sqlite:///mlflow.db")
```

## Соглашение: что откуда берётся

| Поле контракта | Источник в прогоне MLflow |
| --- | --- |
| `run_id` | id прогона MLflow |
| `predictions` | артефакт `predictions.parquet` или `predictions.csv` в каталоге артефактов `mlreview` (обязателен) |
| `examples` | артефакт `examples.parquet` или `examples.csv` в каталоге артефактов `mlreview` (необязателен) |
| `config` | параметры прогона (`log_param`), значения — строки, как их хранит MLflow |
| `curves` | история метрик (`log_metric` со `step`): метрики, у которых не меньше двух точек, в формате `name`, `step`, `value`, отсортированные по `name` и `step`; метрика с одной точкой — итоговое число, а не кривая |
| `data_version` | тег `mlreview.data_version` |

В CSV колонка `example_id` читается как строка (id `007` не превращается в `7`), в остальном типы выводит pandas.

## Ожидаемое поведение

- B1. Дано: прогон с параметрами, историей метрик, тегом `mlreview.data_version` и артефактами `predictions.parquet`, `examples.parquet` · когда `load_mlflow_contract(spec, run_id, tracking_uri=…)` · тогда `RunContract` с `run_id` прогона, `config` из параметров, `curves` из истории метрик, `data_version` из тега и таблицами, равными залогированным.
- B2. Дано: те же таблицы в CSV · тогда контракт тот же; `example_id` в `predictions` и `examples` — строки, `007` остаётся `007`.
- B3. Дано: метрика `auc` с одной точкой и `train_loss` с тремя · тогда в `curves` только `train_loss`; если кривых нет совсем — `curves` равно `None`, и контракт сообщает пробел `curves` (X1).
- B4. Дано: в прогоне только артефакт предсказаний · тогда контракт валиден, `gaps` перечисляет `examples`, `curves`, `config`, `data_version`.
- B5. Дано: `tracking_uri` не передан · тогда используется адрес трекера по умолчанию MLflow (переменная окружения `MLFLOW_TRACKING_URI`).
- B6. Дано: активный прогон MLflow · когда `log_contract_artifacts(predictions, examples=…, data_version=…)` · тогда таблицы записаны в `mlreview/*.parquet` без индекса, версия данных — в тег; `load_mlflow_contract` по этому прогону возвращает таблицы, равные исходным.

### Команда проверки

- C1. Дано: прогон с валидным контрактом · когда `mlreview contract check <run_id> --spec <путь> [--tracking-uri <адрес>]` · тогда код 0; в stdout — «контракт прогона валиден» с id прогона, числом предсказаний, числом примеров и сплитами, числом кривых, числом параметров и версией данных; затем каждый пробел строкой «нет <поле> — недоступно: <назначение>».
- C2. Дано: невалидная спецификация, невалидный контракт или ошибка адаптера (E1–E5) · тогда код 1, в stderr — все проблемы.
- C3. Дано: `mlreview contract` без действия или `mlreview contract check` без id прогона или без `--spec` · тогда ошибка использования от argparse, код 2.

## Деградация и ошибки

Ошибки чтения прогона — `MlflowAdapterError` с сообщением по-русски, где есть id прогона; ошибки содержимого контракта — `RunContractError` из ядра без изменений (все проблемы с путями полей).

- E1. Дано: пакет `mlflow` не установлен · когда вызов адаптера или команды · тогда ошибка с подсказкой `pip install "mlreview[mlflow]"`, а не `ImportError`; остальные команды CLI работают.
- E2. Дано: прогона с таким id нет или трекер недоступен · тогда ошибка «прогон <id> не получен из <адрес трекера>» с причиной от MLflow.
- E3. Дано: в прогоне нет артефакта предсказаний · тогда ошибка, где перечислены оба ожидаемых пути артефакта: `predictions.parquet` и `predictions.csv` в каталоге `mlreview`.
- E4. Дано: таблица залогирована и в parquet, и в CSV · тогда ошибка неоднозначности с обоими путями, а не молчаливый выбор одного.
- E5. Дано: артефакт таблицы не читается (повреждённый parquet, пустой CSV) · тогда ошибка с путём артефакта и причиной.
- E6. Дано: таблицы прочитаны, но не соответствуют формату контракта (в том числе метрика залогирована несколько раз с одним `step` — повтор пары в `curves`) · тогда `RunContractError` из `build_run_contract` с путями полей (FR-C02); адаптер не исправляет данные сам.
- E7. Дано: нет активного прогона MLflow · когда `log_contract_artifacts(...)` · тогда ошибка «нет активного прогона», а не молчаливое создание нового прогона.

## Вне рамок

- Версия и хеш датасета из `mlflow.log_input` (FR-C04, L1), поиск прогонов и выбор референса по эксперименту (S02, L1), проактивный запуск по завершению прогона (FR-R04, L1).
- Адаптеры локальных файлов (FR-C03, L1) и W&B (FR-C03, L2).
- Модели и другие артефакты MLflow, результаты `mlflow.evaluate`.
- Несколько сидов в одном прогоне и вложенные прогоны (FR-D05, L1).
