# Проверки данных

Опора: FR-D03 (пересечения и дубли между сплитами, временная утечка, подозрительно сильные признаки, L0 · Must), B01 (дубли между train и test), B02 (временная утечка), FR-C01 (`data.split_strategy`, `data.time_column`), FR-C02 (`examples` с признаками всех сплитов), S04 (утечка до обучения), X1.

Модуль `mlreview.analyzers.data_checks`; формат находок — `docs/specs/review.md`.

## Правила

- **Признаки** — все колонки `examples`, кроме `example_id`, `split`, сегментов из `task.segments` и `data.time_column`.
- **Порядок сплитов:** `train` → `validation` (также `valid`, `val`, `dev`) → `test` (также `holdout`). Сплиты с другими именами идут после известных, между собой — по алфавиту.
- **Оцениваемые примеры** — строки `examples`, id которых есть в `predictions`; их метки — `predictions.label`.

## Ожидаемое поведение

- B1. Дано: `examples` с train и test, где 9 из 171 строк test по всем признакам совпадают со строками train (другие id) · когда `data_findings(spec, contract)` · тогда находка `data.split_duplicates` severity `critical`: «9 из 171 примеров test (5.3%) полностью совпадают с примерами train по <число> признакам — метрика на test, вероятно, завышена»; доказательства — до 10 id примеров test (по порядку id); в `facts` — `earlier_split`, `later_split`, `duplicates`, `total`, `share`, `features`; предложение — убрать дубли или сплитовать по группам дублей и переоценить.
- B2. Дано: совпадений меньше 1% строк более позднего сплита · тогда severity `medium`. Пары сплитов проверяются все (train–validation, train–test, validation–test), находка — на каждую пару с совпадениями. Пропуски (NaN) в одинаковых позициях считаются совпадением.
- B3. Дано: строки train и test совпадают по признакам и различаются только сегментом или колонкой времени · тогда это дубли: сегменты и время — метаданные, а не признаки.
- B4. Дано: спецификация с `split_strategy: temporal` и `time_column: ts`; в test 40 из 171 примеров раньше последнего примера train · тогда находка `data.temporal_leak` severity `critical`: «40 из 171 примеров test (23.4%) раньше последнего примера train (<время>) при split_strategy: temporal — модель обучена на данных из будущего относительно test»; доказательства — id таких примеров по возрастанию времени; в `facts` — `earlier_split`, `later_split`, `leaked`, `total`, `share`, `boundary`; предложение — сплит по дате отсечки. Совпадение времени с границей утечкой не считается. Колонка времени — число, дата или строка, читаемая как дата.
- B5. Дано: утечка меньше 1% строк более позднего сплита · тогда severity `high`; правильный временной сплит · находок нет.
- B6. Дано: бинарная классификация; числовой признак, по которому оцениваемые примеры разделяются почти идеально (AUC признака против метки или 1 − AUC ≥ 0,99) · тогда находка `data.strong_feature` severity `high`: «признак <имя> почти идеально предсказывает метку на оцениваемых примерах: AUC <значение> (n = <число>) — проверьте утечку таргета»; в `facts` — `feature`, `statistic` (`roc_auc`), `value`, `n`. Для регрессии — |корреляция Спирмена| ≥ 0,99, `statistic` — `spearman`.
- B7. Дано: обычные признаки (сильнейший — AUC около 0,95) · тогда находок `data.strong_feature` нет.

## Деградация и ошибки

Невыполненное попадает в `skipped` с причиной (X1).

- E1. Дано: нет `examples` · тогда все три проверки пропущены: «нет examples».
- E2. Дано: в `examples` один сплит · тогда `data.split_duplicates` и `data.temporal_leak` пропущены: «в examples один сплит».
- E3. Дано: в `examples` нет признаков · тогда `data.split_duplicates` и `data.strong_feature` пропущены: «в examples нет признаков (колонок, кроме example_id, split, сегментов и времени)».
- E4. Дано: `split_strategy` не `temporal` или не задан · тогда `data.temporal_leak` пропущена: «split_strategy в спецификации — <значение> (или «не задан»), а не temporal».
- E5. Дано: колонки времени нет в `examples` · тогда пропуск «нет examples.<колонка>»; колонка не читается как число или дата · пропуск с именем колонки.
- E6. Дано: сплиты с неизвестными именами при временной проверке · тогда пропуск с перечислением этих сплитов и ожидаемых имён; известные сплиты проверяются.
- E7. Дано: multiclass · тогда `data.strong_feature` пропущена: «на L0 — только для бинарной классификации и регрессии». Нечисловые признаки или признаки, где меньше 30 непустых значений, один класс или константа, не проверяются и перечисляются в пропуске.

## Вне рамок

- Почти-дубли (по расстоянию), дубли внутри сплита, утечка через группы (S21, B13 — предложение).
- Утечка таргета через признак как дефект бенчмарка (B03 — L1); нечисловые признаки и multiclass в проверке сильных признаков.
- Препроцессинг на всём датасете и аугментации на валидации (B04, B10 — L2).
- Анализ на выборке для данных, не помещающихся в память (S04).
