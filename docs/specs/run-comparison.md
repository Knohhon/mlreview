# Метрики прогона и сравнение прогонов

Опора: FR-D01 (сравнение прогонов: дельты метрик с доверительными интервалами и значимостью, L0 · Must), FR-C02 (контракт прогона — источник предсказаний и меток), FR-C01 (`task.type · task.output` задают набор метрик по умолчанию), FR-M02 (метрики из раздела `metrics:`), S02 (ревью после прогона: дельты с интервалами), S06 (значимость улучшения), NFR-05 (фиксированный сид бутстрапа), NFR-03 (без LLM), X1 (явная деградация).

Модули: `mlreview.analyzers.evaluation` (метрики, бутстрап) и `mlreview.analyzers.comparison` (находки `metrics.value` и `comparison.metric_delta`). Формат находок и отчёта — `docs/specs/review.md`.

## Метрики

Если в спецификации есть раздел `metrics:`, метрики — его `primary` и `secondary` (`docs/specs/metrics.md`). Иначе набор метрик определяется парой `task.type · task.output` по таблице ниже. Первая метрика — **основная** (по ней работают срезы, `docs/specs/slices.md`).

| `task.type · task.output` | Метрики (первая — основная) |
| --- | --- |
| `classification/binary · labels` | `f1`, `accuracy`, `precision`, `recall` |
| `classification/binary · probabilities` | `roc_auc`, `log_loss`, `brier` |
| `classification/binary · scores` | `roc_auc` |
| `classification/multiclass · labels` | `macro_f1`, `accuracy` |
| `classification/multiclass · probabilities` | `macro_f1`, `accuracy`, `log_loss` |
| `classification/multiclass · scores` | `macro_f1`, `accuracy` |
| `regression · values` | `mae`, `rmse` |

Определения (положительный класс бинарной задачи — 1):

- `accuracy` — доля совпадений метки и предсказания; для multiclass с `probabilities`/`scores` предсказанный класс — колонка `prediction:<класс>` с наибольшим значением (при равенстве — первая по порядку колонок). Метки multiclass сравниваются как строки.
- `precision` = TP / (TP + FP), `recall` = TP / (TP + FN), `f1` = 2TP / (2TP + FP + FN); при нулевом знаменателе метрика не определена.
- `macro_f1` — среднее F1 по классам, встречающимся в метках или предсказаниях.
- `roc_auc` — по рангам (Манн — Уитни, равные значения — средний ранг); не определена, если в выборке один класс.
- `log_loss` — средний минус логарифм вероятности истинного класса, вероятности обрезаются до [1e-15, 1 − 1e-15]; `brier` — средний квадрат разности вероятности и метки.
- `mae`, `rmse` — средняя абсолютная ошибка и корень из средней квадратичной.

Больше — лучше: `accuracy`, `precision`, `recall`, `f1`, `macro_f1`, `roc_auc`. Меньше — лучше: `log_loss`, `brier`, `mae`, `rmse`.

## Бутстрап

- 1000 бутстрап-выборок, генератор `numpy.random.default_rng(0)` создаётся заново для каждой оценки: результат не зависит от порядка вызовов (NFR-05).
- Интервал — перцентильный 95% (2,5 и 97,5 перцентили).
- Выборки, на которых метрика не определена, отбрасываются; если отброшено больше 10% — оценка считается неустойчивой и не выдаётся (E4).
- Парная оценка (два прогона): выборки — индексы общих примеров, статистика — метрика кандидата минус метрика базового прогона на одной и той же выборке.
- p-значение (двустороннее) = min(1, 2 · min(доля дельт ≤ 0, доля дельт ≥ 0)).
- Дельта значима, если 95% интервал не содержит 0.

Бутстрап ROC AUC считается через веса повторов по один раз отсортированным оценкам: значение то же, что у ROC AUC на выборке с повторами, но без пересортировки на каждой выборке (NFR-06, `docs/specs/benchmark.md`).

## Ожидаемое поведение

- B1. Дано: предсказания с известными значениями метрик (например, бинарные вероятности, где `roc_auc` = 0,75, `log_loss` и `brier` посчитаны вручную; регрессия с `mae` = 1,0 и `rmse` = √1,5) · когда считаются метрики · тогда значения совпадают с ручным расчётом до 1e-9; для каждой пары из таблицы набор и порядок метрик — как в таблице.
- B2. Дано: один прогон без базового · когда `run_metrics(spec, contract)` · тогда по находке `metrics.value` (severity `info`) на каждую метрику набора: «<метрика> = <значение>, 95% CI [<низ>; <верх>], n = <число примеров>»; в `facts` — `metric`, `value`, `ci_low`, `ci_high`, `n`; низ ≤ значение ≤ верх.
- B3. Дано: базовый прогон и кандидат на одних примерах, кандидат заметно лучше по основной метрике · когда `compare_runs(spec, candidate, baseline)` · тогда находка `comparison.metric_delta` по каждой метрике: «<метрика>: <база> → <кандидат>, Δ <дельта со знаком>, 95% CI [<низ>; <верх>] — значимо, лучше»; severity `info`; в `facts` — `metric`, `baseline`, `candidate`, `delta`, `ci_low`, `ci_high`, `p_value`, `n`.
- B4. Дано: кандидат значимо хуже · тогда «— значимо, хуже»; severity `high` для основной метрики и `medium` для остальных. Для метрик «меньше — лучше» хуже — это рост значения.
- B5. Дано: прогоны с одинаковыми предсказаниями (или разница внутри шума) · тогда «— в пределах шума (CI включает 0)», severity `info`.
- B6. Дано: прогоны с частично совпадающими `example_id` · тогда сравнение идёт по общим примерам, `n` в фактах — их число; порядок строк в таблицах предсказаний не влияет на результат.
- B7. Дано: одинаковые входы · когда анализ повторяется · тогда находки идентичны, включая интервалы (NFR-05).

## Деградация и ошибки

Невыполненная проверка попадает в `skipped` отчёта с причиной; остальные проверки работают (X1).

- E1. Дано: у прогонов нет общих `example_id` · тогда `comparison.metric_delta` пропущена с причиной «у прогонов нет общих примеров — парное сравнение невозможно».
- E2. Дано: у общих примеров различаются метки · тогда сравнение пропущено с причиной, где число таких примеров и до пяти id: прогоны оценены на разных данных.
- E3. Дано: метрика не определена на всех примерах (например, `roc_auc`, когда в предсказаниях один класс) · тогда эта метрика пропущена с причиной «<метрика> не определена: …», остальные метрики считаются.
- E4. Дано: метрика не определена больше чем на 10% бутстрап-выборок · тогда метрика пропущена с причиной «<метрика>: оценка неустойчива …».
