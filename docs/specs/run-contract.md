# Контракт прогона

Опора: FR-C02 (контракт прогона), FR-C01 (формат предсказаний задаётся `task.type` и `task.output`); потребители — FR-C03 (адаптер MLflow собирает контракт), FR-D01 (сравнение прогонов по id примеров), FR-D02 (срезы по `task.segments`), FR-D03 (B01 — дубли между сплитами, B02 — временная утечка по `data.time_column`); X1 (неполный контракт), S27 (адаптер сообщает, каких полей не хватает); NFR-01 (ядро работает только с контрактом, не с моделью).

Контракт прогона — минимальный набор артефактов прогона, с которым работают анализаторы. Модуль `mlreview.core.run_contract` собирает контракт из таблиц pandas и словарей, проверяет его против спецификации задачи и возвращает неизменяемый `RunContract`; при ошибках поднимает `RunContractError` со списком всех найденных проблем. Адаптеры (MLflow — FR-C03) переводят свои артефакты в этот вызов; ядро не знает, откуда пришли данные.

```python
contract = build_run_contract(
    spec,  # TaskSpec (FR-C01): тип задачи и выход определяют формат предсказаний
    run_id="exp-043",
    predictions=predictions,  # обязательно: DataFrame
    examples=examples,  # необязательно: DataFrame с метаданными примеров всех сплитов
    config={"C": 1.0},  # необязательно: параметры прогона
    curves=curves,  # необязательно: DataFrame кривых обучения
    data_version="ds-v3",  # необязательно
)
contract.gaps  # чего не хватает и какие проверки из-за этого недоступны (X1)
```

## Формат

**`predictions`** — по строке на пример оцениваемого сплита:

| Колонка | Обязательна | Содержимое |
| --- | --- | --- |
| `example_id` | да | id примера; без пропусков, уникален |
| `label` | да | истинная метка; без пропусков |
| `prediction` | для всех, кроме multiclass с `probabilities`/`scores` | предсказание, см. таблицу ниже |
| `prediction:<класс>` | multiclass с `probabilities`/`scores` | по колонке на класс, не меньше двух |

Другие колонки недопустимы: метаданные примеров передаются в `examples`.

| `task.type · task.output` | `label` | предсказание |
| --- | --- | --- |
| `regression · values` | конечное число | `prediction`: конечное число |
| `classification/binary · labels` | 0 или 1 | `prediction`: 0 или 1 |
| `classification/binary · probabilities` | 0 или 1 | `prediction`: вероятность класса 1, число в [0, 1] |
| `classification/binary · scores` | 0 или 1 | `prediction`: конечное число, больше — ближе к классу 1 |
| `classification/multiclass · labels` | любое значение | `prediction`: любое значение без пропусков |
| `classification/multiclass · probabilities` | один из классов колонок | `prediction:<класс>`: числа в [0, 1], сумма по строке 1 ± 0,001 |
| `classification/multiclass · scores` | один из классов колонок | `prediction:<класс>`: конечные числа |

Логические `True`/`False` в бинарной классификации принимаются как 1/0.

**`examples`** — по строке на пример любого сплита (train, validation, test…): обязательные колонки `example_id` (без пропусков, уникален) и `split` (непустая строка); остальные колонки — метаданные и признаки примера (сегменты из `task.segments`, колонка времени из `data.time_column`). Каждый `example_id` из `predictions` должен быть в `examples`.

**`config`** — словарь со строковыми ключами (параметры прогона).

**`curves`** — кривые обучения в длинном формате: колонки `name` (строка, например `val_loss`), `step` (целое ≥ 0), `value` (число; NaN допустим — расходимость обучения тоже сигнал). Пара (`name`, `step`) уникальна.

**`data_version`** — строка; число приводится к строке, как в спецификации задачи.

## Ожидаемое поведение

- B1. Дано: спецификация `classification/binary · probabilities`, все поля контракта валидны · когда `build_run_contract(...)` · тогда возвращается `RunContract` с теми же `run_id`, `config`, `data_version` и таблицами, равными переданным (индекс таблиц сбрасывается в 0…n−1), а `gaps` пуст.
- B2. Дано: каждая допустимая пара `task.type · task.output` из таблицы (кроме multilabel) с валидными для неё `predictions` · когда сборка · тогда контракт валиден.
- B3. Дано: только `run_id` и `predictions` · когда сборка · тогда контракт валиден, `examples` и `curves` — `None`, `config` — пустой словарь, `data_version` — `None`.
- B4. Дано: контракт собран, затем исходные DataFrame и словарь `config` изменены вызывающим кодом · тогда содержимое контракта не меняется (контракт хранит копии; это нужно для воспроизводимости фактов, NFR-05).
- B5. Дано: `data_version=3` · тогда `contract.data_version == "3"`.

### Пробелы контракта (X1)

`contract.gaps` — список `ContractGap(field, purpose)` в фиксированном порядке: недостающее поле и что из-за него не будет проверено. Пробел — не ошибка: контракт валиден, остальные анализаторы работают.

- G1. Дано: нет `examples` · тогда пробел `examples` с назначением «срезы по сегментам (FR-D02), проверки данных между сплитами (FR-D03)».
- G2. Дано: `examples` есть, но в них нет колонки сегмента из `task.segments` · тогда пробел `examples.<сегмент>` на каждый такой сегмент, назначение «срез по сегменту <сегмент> (FR-D02)».
- G3. Дано: в спецификации `data.time_column`, а в `examples` такой колонки нет · тогда пробел `examples.<колонка>`, назначение «проверка временной утечки (FR-D03, B02)».
- G4. Дано: в `examples` один сплит · тогда пробел `examples.split`, назначение «нужно не меньше двух сплитов: проверка дублей между сплитами (FR-D03, B01)».
- G5. Дано: нет `curves` · тогда пробел `curves`, «анализ кривых обучения (FR-D04)»; нет `config` или он пуст · пробел `config`, «логические проверки процесса (FR-D06)»; нет `data_version` · пробел `data_version`, «сверка версий данных между прогонами (FR-C04, FR-D06)».
- G6. Порядок пробелов: `examples`, `examples.<сегменты>` в порядке спецификации, `examples.<колонка времени>`, `examples.split`, `curves`, `config`, `data_version`.

## Деградация и ошибки

Все ошибки — `RunContractError`; сообщение по-русски начинается с «прогон <run_id>: контракт прогона невалиден», у каждой проблемы путь вида `predictions.label` или `examples.example_id`. Перечисляются все проблемы сразу. Где проблема касается конкретных строк, в сообщении — их число и до пяти примеров id (доказательства, как у находок).

- E1. Дано: `run_id` пуст или не строка · тогда ошибка с путём `run_id`.
- E2. Дано: `predictions` не DataFrame или пуст · тогда ошибка с путём `predictions`.
- E3. Дано: в `predictions` нет `example_id`, `label` или нужной колонки предсказания · тогда ошибка «обязательная колонка» с путём колонки; есть лишняя колонка · ошибка «неизвестная колонка» с подсказкой, что метаданные передаются в `examples`.
- E4. Дано: пропуски или повторы `example_id` в `predictions` или `examples` · тогда ошибка с путём `<таблица>.example_id`, числом и примерами id (для пропусков — номера строк).
- E5. Дано: пропуски в `label` или в предсказании · тогда ошибка с путём колонки, числом строк и примерами id.
- E6. Дано: значения не по таблице формата — нечисловое или бесконечное `prediction` в регрессии, `label` не 0/1 в бинарной классификации, вероятность вне [0, 1], сумма вероятностей multiclass не 1, метка multiclass без колонки `prediction:<класс>`, меньше двух колонок классов · тогда ошибка с путём колонки, числом строк и примерами id; в сообщении — ожидаемый формат. Для суммы вероятностей и числа колонок классов путь — `predictions`.
- E7. Дано: `task.type: classification/multilabel` · тогда ошибка с путём `predictions`: формат предсказаний multilabel на L0 не поддерживается — явный отказ, а не молчаливый разбор.
- E8. Дано: `examples` без `example_id` или `split`, с пустыми `split`, или в `predictions` есть id, которых нет в `examples` · тогда ошибка с путём колонки (для отсутствующих id — `predictions.example_id`) и примерами id.
- E9. Дано: `curves` без колонок `name`/`step`/`value`, с нецелым или отрицательным `step`, нечисловым `value` или повтором пары (`name`, `step`) · тогда ошибка с путём колонки (для повтора пары — `curves`).
- E10. Дано: `config` не словарь или с нестроковыми ключами · тогда ошибка с путём `config`.
- E11. Дано: несколько ошибок сразу (E1 + E5 + E8) · тогда все перечислены в одной `RunContractError`.

## Вне рамок

- Чтение контракта из MLflow — в адаптере (`docs/specs/mlflow-adapter.md`, команда `mlreview contract check`); из локальных файлов parquet/csv — FR-C03, L1.
- Формат multilabel, предсказания для нескольких сплитов в одном прогоне, несколько сидов в одном контракте (FR-D05, L1).
- Хеш датасета и сверка `data_version` со спецификацией и между прогонами (FR-C04, FR-D06, B07 — L1).
- Привязка пробелов к конкретным анализаторам и пропуск анализаторов в отчёте — вместе с анализаторами (FR-D01–D03); контракт только сообщает, каких полей нет и для чего они нужны.
- Проверка типа колонки времени и разделение колонок `examples` на признаки и метаданные — в проверках данных (FR-D03).
- Версия формата контракта и миграции (NFR-10, L2).
