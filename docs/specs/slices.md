# Срезы по сегментам

Опора: FR-D02 (срезы: сегменты хуже среднего и регрессии по сегментам между прогонами, L0 · Must), B12 (регрессия в сегменте при росте средней метрики), FR-C01 (`task.segments`), FR-C02 (сегменты — колонки `examples`), S02 (регрессия сегмента в ревью), NFR-05, X1.

Модуль `mlreview.analyzers.slices`; метрики и бутстрап — `docs/specs/run-comparison.md`, формат находок — `docs/specs/review.md`.

## Правила

- Сегменты — колонки `examples` из `task.segments`; значение сегмента у примера берётся из `examples` кандидата и сравнивается как строка, пропуск — отдельное значение `<пропуск>`.
- Метрика — основная метрика задачи: `metrics.primary` спецификации или первая в наборе по умолчанию (`docs/specs/run-comparison.md`).
- Значение сегмента проверяется, если в нём не меньше 30 оцениваемых примеров (а для «хуже остальных» — и вне его не меньше 30).
- Значимость — по p-значению бутстрапа с поправкой Холма на все проверенные значения всех сегментов внутри одной проверки, уровень 0,05; сообщается только ухудшение.
- Доказательства — до 10 id примеров сегмента с наибольшей ошибкой (для регрессии сегмента — с наибольшим ростом ошибки), при равенстве — по id. Ошибка примера: бинарные вероятности — |метка − вероятность|; метки (бинарные и multiclass) и multiclass `scores` — 1 при неверном классе, иначе 0; multiclass `probabilities` — 1 − вероятность истинного класса; регрессия — |метка − предсказание|; бинарные `scores` — не определена (доказательств нет).

## Ожидаемое поведение

- B1. Дано: прогон, где сегмент `size=large` заметно хуже остальных примеров по основной метрике · когда `segment_findings(spec, contract)` · тогда находка `slices.segment_worse` severity `medium`: «сегмент size=large хуже остальных: <метрика> <значение> против <значение вне сегмента> (Δ <дельта>, 95% CI [<низ>; <верх>], n = <число>)»; в `facts` — `segment`, `value`, `metric`, `segment_metric`, `rest_metric`, `delta`, `ci_low`, `ci_high`, `p_value` (с поправкой Холма), `n`; в доказательствах — id примеров сегмента с наибольшей ошибкой.
- B2. Дано: сегменты без разницы в качестве · тогда находок `slices.segment_worse` нет.
- B3. Дано: базовый прогон и кандидат на одних примерах; кандидат лучше в целом, но значимо хуже на `size=small` (B12) · когда `segment_findings(spec, contract, baseline)` · тогда находка `slices.segment_regression` severity `high`: «регрессия сегмента size=small: <метрика> <база> → <кандидат> (Δ <дельта>, 95% CI [<низ>; <верх>], n = <число>); в целом по прогону Δ <общая дельта>»; в `facts` — `segment`, `value`, `metric`, `baseline`, `candidate`, `delta`, `ci_low`, `ci_high`, `p_value`, `n`, `overall_delta`; доказательства — id с наибольшим ростом ошибки.
- B4. Дано: базовый прогон и кандидат с одинаковыми предсказаниями · тогда находок `slices.segment_regression` нет.
- B5. Дано: для метрики «меньше — лучше» (регрессия, `mae`) сегмент с выросшей ошибкой · тогда он считается ухудшением (B1, B3 работают и для регрессии).
- B6. Дано: одинаковые входы · тогда находки идентичны (NFR-05).

## Деградация и ошибки

Невыполненное попадает в `skipped` с причиной (X1).

- E1. Дано: в спецификации нет `task.segments` · тогда обе проверки пропущены: «в спецификации нет task.segments».
- E2. Дано: нет `examples` · тогда проверки пропущены: «нет examples — значения сегментов неизвестны».
- E3. Дано: колонки сегмента нет в `examples` · тогда пропуск с причиной «нет examples.<сегмент>»; другие сегменты проверяются.
- E4. Дано: у значения сегмента меньше 30 примеров · тогда пропуск «<сегмент>: значения с менее чем 30 примерами не проверены: <значение> (<число>), …» (значения по алфавиту).
- E5. Дано: основная метрика не определена на сегменте (например, один класс для `roc_auc`) или оценка неустойчива · тогда пропуск с причиной, где назван сегмент и значение.
- E6. Дано: нет базового прогона · тогда `slices.segment_regression` не запускается и не попадает в `skipped` (это не пробел контракта, а другой режим). Нет общих примеров или метки различаются · тогда пропуск с причиной, как в `docs/specs/run-comparison.md` (E1, E2).

## Вне рамок

- Пересечения сегментов (`size × language`), автоматический поиск плохих срезов без объявленных сегментов.
- Шумные метки в сегменте (FR-D09, B06 — L2), гипотезы о причинах регрессии — LLM-слой (`docs/specs/llm.md`).
