# Спецификации ожидаемого поведения

Любая разработка начинается здесь: сначала фиксируется ожидаемое поведение, затем пишутся тесты под него и только потом — код.

Один файл — одна фича или модуль: `docs/specs/<краткое-имя>.md`. Шаблон:

```markdown
# <Название>

Опора: FR-…, NFR-…, S…, B… (из `docs/MLReview-analysis.md` и `docs/User-cases-MLReview.md`)

## Ожидаемое поведение

- B1. Дано … · когда … · тогда …
- B2. …

## Деградация и ошибки

- E1. Дано … · когда … · тогда инструмент явно сообщает …

## Вне рамок

- …

## Тесты

- B1 → `tests/test_<модуль>.py::test_<имя>`
```

Каждый пункт поведения (B*, E*) покрывается хотя бы одним тестом; тест ссылается на пункт в докстринге, например `"""B1: …"""`. При изменении поведения сначала правится спецификация, затем тесты, затем код.
