# Тестовые стражи архитектурных инвариантов

Опора: NFR-01, NFR-03, NFR-04, S16.

## Ожидаемое поведение

- B1. Дано: модуль пакета `mlreview` вне `mlreview.adapters` · когда он импортирует фреймворк обучения или трекер (sklearn, torch, tensorflow, keras, jax, xgboost, lightgbm, catboost, mlflow, wandb) · тогда тест архитектуры падает и называет файл и импорт.
- B2. Дано: модуль в `mlreview.adapters` · когда он импортирует трекер · тогда тест архитектуры не падает (интеграции живут в адаптерах и extras).
- B3. Дано: любой тест · когда код пытается открыть сетевое соединение по TCP/UDP (IPv4/IPv6) · тогда соединение не устанавливается и поднимается исключение с понятным сообщением. Тесты работают офлайн.
- B4. Дано: любой тест · когда код использует локальные Unix-сокеты · тогда это не блокируется.

## Вне рамок

- Аудит содержимого исходящих запросов к LLM (NFR-04 целиком) — появится вместе с LLM-слоем.

## Тесты

- B1, B2 → `tests/test_architecture.py`
- B3, B4 → `tests/test_offline.py`
