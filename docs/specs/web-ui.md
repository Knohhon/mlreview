# Локальный Web UI — P0

Опора: FR-C01–C06, FR-R01, FR-R03–R05, NFR-01, NFR-03–05;
продуктовый дизайн: `docs/MLReview_Web_UI_Spec.md`.

## Ожидаемое поведение

- B1. Дано workspace · когда запускают `ui` · тогда loopback-сервер отдаёт SPA,
  API v1 и прямые ссылки; явный project приоритетнее окружения.
- B2. Даны зарегистрированные источники · когда обновляют индекс · тогда стабильные
  source:id, поиск, фильтры и пагинация работают без загрузки всех predictions.
- B3. Дан прогон · когда проверяют контракт или запускают ревью · тогда общий Python API
  возвращает те же факты и пропуски, что CLI; задание имеет сохраняемое состояние.
- B4. Дан отчёт · когда сервер перезапущен · тогда последний отчёт контекста доступен;
  изменение spec/источника помечает его устаревшим; незавершённые задания прерваны.
- B5. Даны findings и journal · когда пользователь меняет статус или добавляет решение ·
  тогда общий Store сохраняет изменения, доступные CLI, с прежней семантикой.
- B6. Дан task.yaml · когда сохраняют валидную форму/YAML с текущим ETag · тогда
  файл заменяется атомарно с backup; неизвестные настройки config сохраняются.
- B7. Даны 2–5 прогонов · когда выбран baseline · тогда сравнение выполняется ядром,
  версии данных и несовместимость видимы до запуска; baseline не угадывается.
- B8. Даны offline files-only данные · когда открывают UI · тогда все P0 сценарии работают
  без LLM, CDN и телеметрии, с русскими сообщениями и доступной навигацией.

## Деградация и ошибки

- E1. Дано отсутствие workspace/web extra или занятый порт · когда запускают UI ·
  тогда ошибка объясняет восстановление, не создаёт workspace и не меняет порт.
- E2. Дан недоступный источник/неполный контракт · когда просматривают UI · тогда
  остальные источники и Store доступны, причины ошибок и пропусков явны.
- E3. Дан чужой Origin/Host, неверный CSRF или небезопасный путь · когда обращаются
  к серверу · тогда доступ запрещён; symlink не выходит из разрешённых корней.
- E4. Дан изменённый YAML · когда сохраняют со старым ETag · тогда 409 без перезаписи.
- E5. Даны разные источники с одним native ID · когда записывают ревью через API/CLI ·
  тогда коллизия отклоняется до изменения Store. Существующие ID не мигрируют.
- E6. Дана custom Python-метрика · когда Web запускает вычисления · тогда явная ошибка
  без импорта Python-файла; чтение/редактирование спецификации доступно.
- E7. Даны секреты/HTML в метаданных · когда формируется UI · тогда секреты скрыты,
  текст экранирован, сырые таблицы не передаются; неизвестный API возвращает JSON 404.

## Вне рамок

P1: история reviews, страницы experiments, metrics/playbooks, LLM, экспорт кода,
управление watch. Удалённый доступ и аккаунты отсутствуют. Отчёт хранится как latest
по контексту; статусы находок читаются из Store, а не из исторического снимка.

## Тесты

B1–B8, E1–E7 → `tests/test_web.py`, `frontend/src/App.test.tsx`, `frontend/e2e.spec.ts`.
Проверки HTTP используют ASGI transport без сети; browser E2E запускается отдельно.

## Запуск и разработка

```bash
python -m pip install -e ".[web]"
mlreview init
mlreview ui --no-browser
# http://127.0.0.1:8765/ → setup либо overview
mlreview ui --project /path/to/project --port 8766
```

`--project` указывает корень проекта, а `MLREVIEW_HOME` — каталог `.mlreview`.
При явном project переменная окружения не участвует в выборе. Порт не меняется
автоматически. Внешний bind не поддерживается, для headless используйте SSH tunnel.

Frontend: Node >=22.12, `cd frontend && npm ci && npm run build && npm test`.
`npm run format:check` проверяет формат. Собранные assets входят в Python wheel
из `src/mlreview/web/static`; Node при установке и запуске пакета не используется.
Browser E2E: `npx playwright install chromium`, затем `npm run e2e`; сценарии
создают временный workspace, не изменяют `.mlreview` разработчика.

## HTTP и состояние

- `/api/v1`: health/workspace/overview; sources (добавление, редактирование,
  проверка, удаление, refresh); runs (поиск/пагинация/детали/contract-check/review);
  reviews (POST), jobs; findings (список, детали, status); journal; task
  (чтение, select, validate, PUT); settings. Pydantic/OpenAPI описывают входы.
- Мутации требуют совпадающего Origin и `X-CSRF-Token` из workspace; Host только
  loopback, CORS не включён. Запросы из браузера используют один origin.
- `config.yaml` → `web.sources`, `web.task_path`; UUID источника не зависит от имени. Простые native ID сохраняются; остальные кодируются
  как `~<base64url UTF-8>` внутри namespace, затем весь ID URL-encoded; `/review` внутри native ID не становится маршрутом.
  Секреты не допускаются в Tracking URI; учётные данные задаются окружением.
- `.mlreview/web.sqlite`: восстанавливаемый каталог metadata, persistent jobs и
  latest reports. Предметные findings/journal остаются в `store.sqlite`.
- Очередь: один worker, не более 16 принятых заданий. При штатной остановке принятые
  задания завершаются; после аварийного рестарта queued/running → interrupted.
- Контекст отчёта: кандидат, baseline, группы сидов и выбранные анализаторы.
  Свежесть: hash текста task, версия MLReview, источники и fingerprints файлов;
  для MLflow проверяется контракт. Snapshot сохраняет точный JSON ядра, текущий
  статус находки читается из Store. Без snapshot находки CLI всё равно доступны.
- Таблица файловых прогонов индексирует metadata без predictions. Метрики появляются
  после открытия карточки; отсутствующие значения отображаются прочерком. Refresh
  сбрасывает derived metadata; недоступность источника сохраняет предыдущий каталог.
- Редактор YAML показывает старый и новый текст; Save доступен после просмотра.
  ETag сравнивается с актуальным содержимым, backup — соседний `<file>.bak`.
  Внешний task разрешается выбором конкретного файла, внешние runs — регистрацией
  каталога. Подмена разрешённого пути символической ссылкой запрещена.
