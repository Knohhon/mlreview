# Интерфейс анализаторов и группы ревью

Опора: FR-E01 (плагины анализаторов с единым интерфейсом — L1 · Should, внутренний), FR-R01 (`review`, `diagnose`), FR-D01–D08, X1 (что не проверено и почему), NFR-03, NFR-05.

Анализатор — детерминированная проверка с единым интерфейсом: на входе контекст ревью, на выходе находки и пропуски (`CheckResults`). `review()` запускает зарегистрированные анализаторы выбранных групп.

```python
from mlreview.analyzers.registry import Analyzer, ReviewContext, register


def my_check(ctx: ReviewContext) -> CheckResults: ...


register(Analyzer(name="my", group="data", requirement="FR-…", run=my_check))
```

`ReviewContext`: `spec`, `contract` (кандидат), `baseline` (или `None`), `candidate_seeds` и `baseline_seeds` — другие прогоны той же конфигурации по сидам (кортежи контрактов), `prior_runs` — сколько других прогонов на тех же данных уже прошло ревью (из хранилища; `None` — хранилища нет).

## Группы

| Группа | Анализаторы | Спецификация |
| --- | --- | --- |
| `data` | проверки данных | `docs/specs/data-checks.md` |
| `segments` | срезы | `docs/specs/slices.md` |
| `metrics` | метрики и сравнение, пригодность метрик, разброс по сидам, калибровка, расхождение моделей | `run-comparison.md`, `metrics.md`, `seeds.md`, `calibration.md` |
| `curves` | кривые обучения | `docs/specs/learning-curves.md` |
| `process` | логические проверки процесса | `docs/specs/process-checks.md` |

Порядок групп и пропусков в отчёте — `data`, `segments`, `metrics`, `curves`, `process`; внутри группы — порядок регистрации.

## Команды

- `mlreview review <прогон> [<прогон по другому сиду>…] --spec … [--baseline <прогон> [<сид>…]]` — первый прогон каждой стороны основной: по нему считаются данные, срезы, метрики и сравнения; остальные — сиды той же конфигурации (FR-D05).
- `mlreview diagnose data|segments|curves|process <прогон> --spec … [--baseline <прогон>]` — одна группа.

## Ожидаемое поведение

- B1. Дано: зарегистрирован анализатор группы `data` · когда `review(..., groups=("data",))` · тогда его находки и пропуски в отчёте после встроенных проверок группы.
- B2. Дано: анализатор бросил исключение · тогда ревью не падает: в `skipped` — «<имя>: ошибка анализатора: <тип>: <сообщение>» (X1), остальные анализаторы работают.
- B3. Дано: неизвестная группа · тогда `ValueError` со списком допустимых.
- B4. Дано: `review(spec, c, b, candidate_seeds=(c2, c3), baseline_seeds=(b2, b3))` · тогда анализатор сидов получает по три прогона на сторону; остальные анализаторы работают по основным прогонам.
- B5. Дано: `review A1 A2 A3 --spec … --baseline B1 B2 B3` · тогда в отчёте `run_id` — A1, `baseline_id` — B1, `candidate_seeds` — `[A2, A3]`, `baseline_seeds` — `[B2, B3]` (в JSON).
- B6. Дано: `diagnose curves` / `diagnose process` · тогда только находки и пропуски этих групп.

## Деградация и ошибки

- E1. Дано: в контексте нет данных, нужных анализатору (нет кривых, конфига, базового прогона, хранилища) · тогда в `skipped` одна запись на анализатор или проверку с причиной; находки других анализаторов на месте.

## Вне рамок

- Публичные плагины из внешних пакетов через entry points (FR-E01 — L2), шаблон контрибьюции (FR-E03).
