# Настройки и проверки Codex

Область: инструменты разработки репозитория, без изменения поведения MLReview.
Настройки Claude Code сохраняются независимо.

## Ожидаемое поведение

- B1. Дано существующее грязное дерево · когда запускается сессия · тогда хук
  запоминает содержимое доступных файлов проекта, исключая архивы диалогов,
  служебное состояние и игнорируемые Git файлы; без новых правок Stop не гоняет тесты.
- B2. Дано изменение Python-файла через patch или shell · когда завершён инструмент ·
  тогда Ruff check и format --check проверяют изменившиеся Python-файлы;
  без изменения содержимого повторной проверки нет. Удалённые файлы не линтятся.
- B3. Дано изменение кода, YAML плейбука или конфигурации тестов/сборки · когда Stop ·
  тогда выполняются Ruff check, Ruff format --check и pytest, независимо от ошибок
  предыдущей команды. Успех запоминается по содержимому; новая правка запускает проверки.
- B4. Дано изменение только документации · когда Stop · тогда полные проверки
  не запускаются, агенту напоминается проверить актуальность документации.
- B5. Дано вызов из подкаталога и произвольный session_id · тогда корень определяется
  расположением скрипта, состояние разделено по сессиям, session_id не задаёт путь.

## Деградация и ошибки

- E1. Дано нет ruff/pytest, команда упала или превысила таймаут · тогда результат
  содержит понятную ошибку и возвращается агенту как blocking feedback, без установки
  зависимостей и изменения файлов. Неуспешный результат не кэшируется как успех.
- E2. Дано Stop уже возобновил ход (`stop_hook_active`) · тогда повторный Stop
  не создаёт цикл; обычные проверки после следующей правки сохраняются.
- E3. Дано отсутствующее/повреждённое состояние · тогда PostToolUse/Stop проверяют
  доступные кандидаты Git, чтобы отсутствие SessionStart не скрывало изменения.
- E4. Дано некорректный stdin или неизвестный режим · тогда скрипт явно сообщает
  об ошибке и не выдаёт успешную проверку; содержимое входных данных не выводится.

## Вне рамок

- Полная блокировка чтения диалогов на уровне файловой системы, запись транскриптов,
  изменение доверия к хукам, глобальных настроек или прав доступа Codex.
- Автоисправления, установка пакетов, Git commit/push, внешние LLM-запросы.

## Тесты

B1–B5, E1–E4: `tests/test_codex_hooks.py`. Хуки тестируются в отдельных временных
Git-репозиториях без сети, MLReview и пользовательских данных; внешние проверки
подменяются. Формат конфигурации дополнительно проверяется установленным Codex.
