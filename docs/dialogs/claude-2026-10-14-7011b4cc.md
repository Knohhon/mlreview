## 2. CLI и Python API вручную (5 минут, без MLflow)

**Спецификация задачи (FR-C01).** Создайте файл `task.yaml`:

```yaml
task:
  type: classification/binary
  output: probabilities
  error_costs: {false_negative: high, false_positive: low}
  segments: [size]
data:
  split_strategy: stratified
  version: v1
```

```bash
mlreview spec validate task.yaml        # → «спецификация валидна…», код 0
```

Чтобы проверить ошибку, испортите какое-нибудь поле, например `split_strategy: random_ish`. Ожидается код 1 и список проблем. Я проверил, сообщение такое: `data.split_strategy: недопустимое значение 'random_ish'; допустимо: random, stratified, temporal`.

**Контракт прогона (FR-C02)** доступен только из Python:

```python
import pandas as pd
from mlreview.core.task_spec import load_task_spec
from mlreview.core.run_contract import build_run_contract

spec = load_task_spec("task.yaml")
preds = pd.DataFrame({"example_id": ["a", "b", "c"], "label": [0, 1, 1],
                      "prediction": [0.1, 0.8, 0.4]})
contract = build_run_contract(spec, run_id="local-1", predictions=preds)
for gap in contract.gaps:
    print(gap)
```

В выводе будет четыре пробела: нет `examples`, `curves`, `config` и `data_version`, и для каждого сказано, какой анализатор из-за этого не сработает (X1). Это тоже проверено. Сломанные данные поднимают `RunContractError` со всеми проблемами сразу: вероятность вне [0, 1], дубли `example_id`, отсутствующая колонка `label` и т. п.

## Что можно запускать

```bash
mlreview review <run_id> --spec task.yaml [--baseline <run_id>] [--format json]
mlreview diagnose data <run_id> --spec task.yaml
mlreview diagnose segments <run_id> --spec task.yaml [--baseline <run_id>]

```

- **Сравнение прогонов (FR-D01).** Набор метрик зависит от типа задачи и выхода. Для каждой метрики — дельта, 95% интервал и вердикт «значимо лучше / значимо хуже / в пределах шума». Интервалы считаются бутстрапом с фиксированным сидом, повторный запуск даёт тот же отчёт.
- **Срезы (FR-D02).** Сегменты, которые хуже остальных, и регрессии сегментов относительно базового прогона (B12). Значимость — с поправкой на число проверенных сегментов. В доказательствах — id примеров с наибольшей ошибкой.
- **Проверки данных (FR-D03).**
  - Дубли между сплитами (B01).
  - Временная утечка (B02) — при `split_strategy: temporal`.
  - Признаки, почти идеально предсказывающие метку: AUC ≥ 0.99 или |корреляция Спирмена| ≥ 0.99.
- **Пороги и правила выбраны мной** — проверьте, устраивают ли:
  - дубли или утечка у ≥ 1% строк позднего сплита — critical;
  - значение сегмента проверяется от 30 примеров.
- **Отчёт.** Находки отсортированы по важности, у каждой есть доказательства и предложение. Что не проверено и почему, перечислено отдельным списком. Последняя строка: «LLM: не используется».
- **`ask` и `metrics`.** `ask` явно отвечает «требует LLM» и возвращает код 1. `metrics` осталась заглушкой: проектирование метрик относится к L1.
- **Бенчмарк.** Каталог `benchmark/`: три датасета из sklearn (breast_cancer, diabetes, digits), в каждом чистая версия и версии с B01, B02, B12.

## Что стоит учесть

- **Производительность.** На 100 тыс. примеров полное ревью с базовым прогоном занимает около 90 с, почти всё время — бутстрап AUC. Это в пределах NFR-06 (≤ 2 мин, требование L1), но запас небольшой. Ускорить можно бутстрапом через веса.
