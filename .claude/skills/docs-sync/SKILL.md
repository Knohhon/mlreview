# Актуализация документации

## 1. Что изменилось

Список изменённых файлов приходит от хука `Stop`. Если скилл вызван вручную:
```bash
git status --short && git diff --stat
```
Не открывать и не учитывать `docs/dialogs/`.

## 2. Автоматические находки

```bash
python .claude/hooks/doc_sync.py report
```
Сообщает битые ссылки на пути в обратных кавычках и FR/NFR, которых нет в `docs/MLReview-analysis.md`. Находка может быть ложной (например, путь намеренно описан как будущий) — тогда лучше переформулировать текст, чтобы он не выглядел ссылкой.

## 3. Внутренние файлы Claude — актуализировать самому

Сверить с изменениями и поправить без отдельного согласия:
- `CLAUDE.md` — команды, статус проекта, архитектура, инварианты, порядок разработки, хуки, ограничения;
- `.claude/skills/*/SKILL.md` — шаги и команды скиллов;
- `.claude/settings.json` — только если изменились скрипты хуков или команды проверок.

Правила: держать CLAUDE.md кратким, не дублировать то, что легко найти в коде; не писать того, что не подтверждено файлами.

## 4. Остальные markdown — предупредить и предложить

Проверить `README.md`, `docs/MLReview-analysis.md`, `docs/User-cases-MLReview.md`, `docs/specs/*.md` на несоответствие изменениям: статус и чек-листы в README, команды и инструкции, описания модулей, спецификации, по которым менялся код, требования (не реализовано ли то, что помечено как план, и наоборот).

В `README.md` — только сведения о продукте. Расхождения, связанные с настройками и процессом работы Claude (`.claude/`, скиллы, хуки, спецификации как процесс, диалоги), для README не предлагать: их место — CLAUDE.md.

**Не править без согласия.** Ответ пользователю:
- по каждому расхождению: файл и место, в чём несоответствие, предлагаемая правка (цитата «было → стало»);
- в конце вопрос, какие правки применить.

Если расхождений нет — одна строка: «Документация соответствует изменениям».
