# Актуальность документации

Определить затронутые файлы через git status --short и целевые git diff.
Не читать диалоги, не запускать неограниченный git diff, включающий docs/dialogs/.
Сверить реализацию с профильными docs/specs/, требованиями docs/MLReview-analysis.md
и пользовательскими командами README.md, docs/quickstart.md,
docs/mlreview_cli_reference.md.

При изменении процесса Codex обновить AGENTS.md, затронутые .agents/skills/
и .codex/config.toml или hooks.json. Не редактировать .claude/ только ради Codex.
Настройки агента не добавлять в продуктовый README.
При изменении поведения обновлять соответствующую спецификацию как часть задачи.
Остальные документы исправлять, если это входит в запрос; иначе дать конкретные
места и предложения. Не запрашивать повторно уже выданное разрешение на документацию.

Для существующей автоматической проверки ссылок и FR/NFR можно выполнить:

```bash
python .claude/hooks/doc_sync.py report
```

Этот режим не изменяет документы или снимки, исключает диалоги, но проверяет
только прежний набор Markdown Claude/README/docs и исходников. Он не проверяет
новые инструкции Codex: ссылки AGENTS.md и .agents/skills/ сверить отдельно.
Не вызывать его режим stop: тот относится к событиям и состоянию Claude Code.
Находки могут описывать запланированные пути; оценивать их по контексту.

Ссылаться на реализованное поведение, не переносить планы в статус «готово».
Результат: исправленные документы либо точные расхождения и предлагаемые правки;
если расхождений нет — кратко сообщить об этом.
