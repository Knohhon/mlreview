# Проверки MLReview

Из корня репозитория активированным Python-окружением выполнить независимо:

```bash
python -m ruff check .
python -m ruff format --check .
python -m pytest -q
```

Выполнить все команды, даже если одна упала. Перед исправлениями сверить
git status --short: не форматировать и не чинить чужие изменения без связи с задачей.
Ошибки тестов сопоставлять со спецификацией, не подгонять ожидания под реализацию.

Если зависимостей нет, использовать окружение проекта либо установить минимальный
набор `python -m pip install -e ".[dev]"` в отдельное виртуальное окружение.
Полный набор для MLflow/MCP/бенчмарка — requirements.txt. Соблюдать ограничения
среды на установку и сеть. Не менять глобальный Python.

Без mlflow, mcp и sklearn соответствующие проверки могут быть пропущены;
сообщить фактические пропуски и их причины. CI проверяет Python 3.10–3.13;
один локальный прогон не заменяет матрицу CI. Не отключать запрет сети в conftest.

Если менялись анализаторы, плейбуки или численные методы:

```bash
python -m benchmark
```

Для изменений производительности — также `python -m benchmark --perf`.
Гейты: Q1 ≥ 70%, Q2 ≤ 1; 100 тыс. примеров без LLM ≤ 120 секунд.
Результат: статус Ruff, формата и pytest, число passed/skipped/failed,
существенные причины падений и какие интеграции реально проверены.

## Web UI

Для изменений `src/mlreview/web/` установить extra `[web,web-test]` и выполнить
`tests/test_web.py` вместе с полной регрессией. При изменении `frontend/` нужен
Node >=22.12; из `frontend/` выполнить `npm run format:check`, `npm run build`,
`npm test`. Сборка обновляет `src/mlreview/web/static` — эти assets входят в wheel.
При изменении сквозных сценариев выполнить `npm run e2e` с Playwright Chromium:
сервер и браузер используют временный workspace, отдельно от pytest. Не отключать
сетевые стражи `tests/conftest.py` для браузерных проверок.
